The v2.146.0 guard was fail-safe-LENIENT (a destination that did not provably fold in-tree PASSED). v5.17.0 replaced it with a FOLD over a scoped AST binding model (`scripts/cpv_write_sink_ast.py::render_destination` + `_ScopeIndex`; `scripts/cpv_inplugin_write_guard.py::_ast_path_findings`; `scripts/cpv_persistence_target.py::_fold_to_plugin_root(raw, plugin_root, self_path)`), NOT a taint engine and NOT the card's earlier "constrain-the-input + manifest key" idea (a self-declared suppression, the #63 shape; CPV's own generators are ASSEMBLED_UNKNOWN so it would have blocked CPV's publish). Tiers: T1 critical when the destination folds in-tree AND carries a literal script suffix from ANY source (concat/f-string/%/.format fragments, .with_suffix/.with_name/.with_stem args, str.replace/re.sub replacement, Name-bound literals, bytes, a `#!` body to an extensionless in-tree path, exec-bit chmod on a foldable path); T2 major `RC-164-UNRESOLVED` when the PREFIX folds in-tree but the tail is computed, for BOTH ROOT and DATA anchors (a WARNING DATA tier re-opens the #152 staged-daemon hole); T3 info, ONE aggregate per file, only when the tail has a script suffix and the root cannot be placed (parameter/hoisted/computed receiver) — else nothing. Params → UNKNOWN, Calls never followed, `AugAssign` breaks the copy chain, the copy predicate reads the SAME binding map; `__file__`/`$0`/`BASH_SOURCE` fold to the concrete `plugin_root/self_path`; `Path.home()` renders as `~`. A parsable `.py` gets the AST sinks PLUS the shell/heredoc/chmod regexes over lines the AST did not claim (`include_py_patterns=False`) — AST-only dispatch was a shell-in-string false negative. Measured on one machine's cache (a baseline, not fleet evidence): the strict flip would have newly rejected 1375 writes / 104 plugins; after the fold T2 = 0, T1 = 11 (all shapes the regex path already blocked); emission A/B over 63 plugins: HEAD 21 CRITICAL / 48 MAJOR → 12 / 39 / 4 MINOR, shell surface 0 lost, every Python delta an `os.chmod(<Name>, …)` on a tmp/pytest/non-exec target HEAD flagged blindly (the janitor's `shutil.copyfile` + chmod staging is a verbatim copy → T3 is the honest verdict). Pre-commit advisor FP fixed: `.with_name("gen.py")` on a slash-less UNKNOWN receiver dropped the `$__UNK_n` marker and rendered a bare literal (critical); the marker now stays the prefix (T3). Card: TRDD-ETDWX70R (archived).
