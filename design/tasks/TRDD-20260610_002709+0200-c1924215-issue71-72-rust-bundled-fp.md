**Fixes (FN-safe precision — no rule deleted, no --strict relaxed):**

1. **Bug 1 — private-path/absolute-path scan walked build-output dirs.**
   `scripts/cpv_validation_common.py`: added `.next` + `vendor` to
   `PRIVATE_INFO_SKIP_DIRS` (already had target/dist/build/node_modules/.venv/
   __pycache__), and changed `extra_skip = skip_dirs or set()` →
   `extra_skip = (skip_dirs or set()) | PRIVATE_INFO_SKIP_DIRS` in BOTH
   `scan_directory_for_private_info` AND `validate_no_absolute_paths`. The
   walk prunes by basename (`gitignore_filter._walk_pathlib`:
   `if entry.name in skip_dirs`), so a nested `tools/x/target/` is now caught
   regardless of the root-only GitignoreFilter. FN-safe: a leaked path in a
   TRACKED file (any dir NOT in the build/dep set) still fires.

2. **Bug 2 — SHELL_EXEC over-fired on Rust `eval` identifiers.** New
   `scripts/_skillaudit_rust_context.py` (`classify(...)` →
   `safe_literal`/`unknown`). Registered `.rs` in `_CLASSIFIER_EXTENSIONS`
   and added the `.rs` dispatch branch in
   `cpv_skillaudit_native._context_classifier_verdict`. Suppresses the
   `eval`-token SHELL_EXEC match (Rust has no shell/runtime-eval builtin);
   real exec (`Command::new`/`std::process`/`.spawn(`/`.output(`/`.status(`/
   `.exec(`) falls through and fires (the `spawn(` pattern). re2-safe (no
   lookaround in the classifier regexes). Python builtin `eval(` in `.py`
   still fires (carve-out is `.rs`-gated).

3. **Bug 3 — AGENT_MEMORY_MOD over-fired on a memory-authoring skill.** New
   `_is_memory_authoring_skill(file_path, content)` +
   `_MEMORY_TERM_RE`/`_MEMORY_AUTHORING_TERM_RE`/`_MEMORY_ATTACK_INTENT_RE`
   in `cpv_skillaudit_native.py`, plus an early `return "suppress"` carve-out
   in `_context_classifier_verdict` (next to the CLAUDE_CLI_UNAUTHORIZED_INSTALL
   one). Suppresses AGENT_MEMORY_MOD when the skill's OWN frontmatter
   name/description declares memory authoring (memory term AND authoring verb,
   voided by an attack-intent term). FN-safe: a non-memory skill, or one that
   openly describes injecting/hijacking ANOTHER agent's memory, still fires
   (demoted-but-visible).

4. **Docs** — `skills/plugin-validation-skill/references/plugin-structure.md`
   gains a "Bundled native binaries (Rust / Go / compiled tools)" subsection
   documenting the canonical `rust/` + `bin/` + `build.sh` layout (the #71
   cross-cutting `tools/` MAJOR ask). CPV already recognises `rust/` and
   `bin/` as standard dirs (validate_plugin.py:1886/1937) — `tools/` stays
   correctly flagged.

**Load-bearing learning — the scan cache is keyed by VERSION, not classifier
code.** The v2.104.0 skillaudit result cache keys on
`(content_hash, _CATALOG_HASH, __version__, file_ext)`. A classifier-code
change at the SAME version is masked by a cache hit, so local testing of a
classifier fix MUST set `CPV_SCAN_CACHE=0` (the new test file's autouse
fixture does this). At publish the version bump is the cache epoch — it
always invalidates between releases, so USERS get the fix. Defensible
as-is (version = cache epoch, guaranteed by the always-bump-on-publish rule);
NOT changing the cache key to hash classifier modules (per-scan cost for zero
user benefit).
