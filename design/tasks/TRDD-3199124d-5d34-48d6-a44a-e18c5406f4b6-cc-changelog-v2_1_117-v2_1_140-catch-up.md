## 3. Implementation plan

### Phase A — Hook `args` field (GAP-1)

**File:** `scripts/validate_hook.py`

**Changes:**
1. In `validate_command_hook()`, accept `args: list[str]` as a valid
   alternative to `command: str` (exec form). Per the changelog:
   "spawns the command directly without a shell, so path placeholders
   never need quoting".
2. If both `command` and `args` are present, emit MAJOR — they are
   mutually exclusive; CC docs don't define which one wins.
3. If neither is present, emit CRITICAL (unchanged from today, which
   says "missing required 'command' field" — message updated to
   "missing required 'command' or 'args' field").
4. If `args` is present, validate:
   - Must be a non-empty `list`.
   - Every element must be a `str`.
   - First element ("argv[0]") gets the same portability checks the
     current `command` field receives (no hardcoded absolute paths,
     interpreter for known script extensions, etc.) — adapted for
     argv form.
5. Add `args` to the substitution / placeholder mention in error
   messages (e.g. `${CLAUDE_PLUGIN_ROOT}` lookup spans both fields).

**Tests:** `tests/test_hook_args_field.py` — 6 cases:
- `args` valid (passes)
- `args` and `command` both present (MAJOR)
- `args` empty list (CRITICAL)
- `args` non-string element (CRITICAL)
- Neither `command` nor `args` (CRITICAL with updated message)
- `args[0]` absolute path without `${CLAUDE_PLUGIN_ROOT}` (MAJOR portability)

### Phase B — Hook `continueOnBlock` field (GAP-2)

**File:** `scripts/validate_hook.py`

**Changes:**
1. After the `validate_command_hook` / `validate_*_hook` dispatchers
   complete, add a cross-cutting check on the parent hook entry's
   `continueOnBlock` field.
2. Rules:
   - Must be a `bool` (CRITICAL if non-bool).
   - Only meaningful for `PostToolUse` events (and `PostToolUseFailure`
     which fires "instead of PostToolUse" — per v2.1.119 `duration_ms`
     entry, same lineage). For all other events, emit MINOR ("ignored
     on `<event>` per v2.1.139 hooks-reference; remove or move to
     `PostToolUse`").
3. Add `continueOnBlock` to the recognized-fields hint surface so it
   doesn't appear in any "unknown field" log path.

**Tests:** `tests/test_hook_continueOnBlock.py` — 4 cases:
- `continueOnBlock: true` on PostToolUse hook (passes)
- `continueOnBlock: false` on PostToolUse hook (passes — explicit-default OK)
- `continueOnBlock: "true"` (CRITICAL — must be bool, not string)
- `continueOnBlock` on `Stop` event (MINOR — ignored on non-PostToolUse)
