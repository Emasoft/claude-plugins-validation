## Problem
`cpv-remote-validate plugin . --strict` (CPV via uvx on bare ubuntu-latest)
prints the `[REPO LINT]` banner then hangs forever (3h+). Intermittent
per-runner (3/4 gate runs). On cancel: uv + 4 python children alive => a
linter child blocked (first-run download stall / stdin in no-TTY / no-timeout
network fetch). Works locally (tools pre-installed, has TTY, warm cache).

## Root cause
`cpv_lint_engine.py` has 18 `subprocess.run` calls; ALL have `timeout=`
and catch `TimeoutExpired`, but NONE set `stdin=subprocess.DEVNULL`. In bare
CI the linters are not on PATH => `smart_exec.choose_best` falls back to
`uvx ruff@latest` / `npx --yes eslint` etc. Those (a) inherit the CI step's
stdin (no TTY) and (b) spawn a GRANDCHILD fetcher. When the timeout fires,
`subprocess.run` only kills the direct child; `communicate()` then blocks
PAST the timeout waiting for the grandchild (which inherited the captured
pipe) to close it. That is exactly the observed "timeout set but still hangs +
orphan children" signature.

## Fix 1 (the hang)
New `_run_linter(cmd, *, timeout, cwd=None)` in cpv_lint_engine.py:
- `stdin=subprocess.DEVNULL` (instant EOF — universal anti-hang),
- non-interactive env (CI=1, DEBIAN_FRONTEND=noninteractive, NPM_CONFIG_YES=true,
  PIP_NO_INPUT=1, UV_NO_PROGRESS=1, GIT_TERMINAL_PROMPT=0),
- Popen in a NEW PROCESS GROUP (start_new_session=True) + on TimeoutExpired
  kill the WHOLE group (killpg) so a forked grandchild cannot keep the pipe
  open past the deadline; returns a CompletedProcess-shaped result.
Route all 18 call sites through it. Harden smart_exec.py's 2 spawns
(get_version:192, CLI run:588) with stdin=DEVNULL too.
