## Issue #27 — phantom skill cross-reference

### Symptom

`validate_xref.cross_reference_skills` emits MAJOR for a phantom skill
name like `amvcp-wf-` (trailing dash + empty suffix). No such skill
exists in the plugin; the plugin ships `amvcp-wf-archetypes`,
`amvcp-wf-devices`, `amvcp-wf-fidelity`, `amvcp-wf-screens` etc.

### Root cause

`SKILL_REF_PATTERN` in `scripts/validate_xref.py:65-68`:

```python
SKILL_REF_PATTERN = re.compile(
    r"(?:skill|skills)/([a-z][a-z0-9-]*)",
    re.IGNORECASE,
)
```

The captured group `[a-z][a-z0-9-]*` allows a trailing hyphen. Body
text like `skills/amvcp-wf-#anchor` or `skills/amvcp-wf-.md` or
`skills/amvcp-wf-)` matches with capture `amvcp-wf-` (the
non-`[a-z0-9-]` boundary char ends the capture, but the trailing dash
is kept). The lowercase comparison then fails — no skill name ends in
a hyphen.

### Fix

Two-layer defense:

1. Tighten the regex to require the last char of the capture be a
   letter or digit (forbid trailing hyphen):

   ```python
   SKILL_REF_PATTERN = re.compile(
       r"(?:skill|skills)/([a-z](?:[a-z0-9-]*[a-z0-9])?)",
       re.IGNORECASE,
   )
   ```

   Logic:
   - `[a-z]` — first char must be a letter
   - `(?:[a-z0-9-]*[a-z0-9])?` — optional tail that, when present,
     ends in a non-hyphen. Single-letter names like `a` still match.

2. Belt-and-suspenders post-filter: drop any captures ending in `-`
   before they reach the cross-reference comparison. Cheap and
   defensive against any future regex variant.

## Issue #29 — gen_mega_linter_yml deprecated DISABLE_REPORTERS

### Symptom

`scripts/generate_plugin_repo.py` `gen_mega_linter_yml` template emits:

```yaml
DISABLE_REPORTERS:
  - GITHUB_COMMENT_REPORTER
```

Mega-Linter v8+ rejects this list-style schema; the JSON Schema now
requires:

```yaml
GITHUB_COMMENT_REPORTER: false
```

### Fix

Replace the two-line block at `scripts/generate_plugin_repo.py:3298-3300`:

```diff
-# Disable reporters that create PR comments (we handle that ourselves)
-DISABLE_REPORTERS:
-  - GITHUB_COMMENT_REPORTER
+# Disable reporters that create PR comments (we handle that ourselves)
+# v8+ boolean form — replaces the deprecated DISABLE_REPORTERS list.
+GITHUB_COMMENT_REPORTER: false
```

### Regression test

Assert the generated template contains the v8+ key and does NOT
contain `DISABLE_REPORTERS:`.

## Issue #28 — cpv.allow_pipeline_drift documented but never implemented

### Symptom

`RC-PIPELINE-DRIFT-001` WARNINGs from `scripts/validate_plugin.py`
instruct the user to add the file to `cpv.allow_pipeline_drift` in
`plugin.json`. Adding the key has no effect — the WARNING continues to
fire. Grep confirms the key is mentioned in WARNING text ONLY; no
consumer code reads it.

### Fix

In `_check_canonical_pipeline_drift` (around `scripts/validate_plugin.py:4471`):

1. After loading `manifest_data`, read the allow-list:

   ```python
   allow_list_raw = manifest_data.get("cpv", {}).get("allow_pipeline_drift", [])
   if not isinstance(allow_list_raw, list):
       allow_list_raw = []
   # Normalize paths (strip whitespace, drop empties) for comparison
   allow_list = {str(p).strip() for p in allow_list_raw if str(p).strip()}
   ```

2. Inside the per-file loop, skip the drift WARNING when
   `rel_path in allow_list`:

   ```python
   if rel_path in allow_list:
       continue
   ```

3. Reword the WARNING help text to clarify the suppression actually
   works ("add the file path to `cpv.allow_pipeline_drift` (a list of
   plugin-root-relative paths) in plugin.json").

### Regression test

Build a fixture plugin with an intentionally-drifted file, run the
validator twice — once without the key (emit WARNING), once with the
key (suppress WARNING).
