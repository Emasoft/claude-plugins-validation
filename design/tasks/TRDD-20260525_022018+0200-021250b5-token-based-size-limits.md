# TRDD-021250b5 — Token-based size limits

**Filename:** `design/tasks/TRDD-20260525_022018+0200-021250b5-token-based-size-limits.md`
**Tracked in:** this repo (design/tasks/ is git-tracked)

## User mandate (verbatim intent)

- "a plugin with skills above 5000 chars is invalid. non negotiable. do not
  provide the means to skip this gate." → remove bypass config.
- "the skill/command/agent description in the frontmatter must be under 200
  chars. no exceptions." → hard description gate.
- Then the WHY: the real limits are in **TOKENS**, not chars; chars were a CJK
  worst-case proxy (CJK ≈ 1 char/tok, English ≈ 3.5–4). "either you keep a very
  big margin … or you use a precise tokenizer." Consider many languages
  (Vietnamese/Thai/Hindi/…).
- Real limits (from docs + an Anthropic Claude-Code engineer YouTube interview;
  the token values are NOT in the docs — only hinted at skills.md "Skill
  descriptions are cut short", an undisclosed rule):
  - **Skill body = 5,000 tokens** (DOCUMENTED: auto-compaction keeps "the first
    5,000 tokens of each" skill; 25k combined budget. skills.md "Skill content
    lifecycle"). Plus the "under 500 lines" tip.
  - **description + when_to_use = 300 tokens** (interview). Split: description
    **200 tok**, when_to_use **100 tok**. (Docs only show the 1,536-CHAR outer
    storage cap + the 1% listing budget; the operative truncation is the
    undisclosed ~300-token rule.)
  - **Agent description = 300 tok** (no separate when_to_use — desc+wtu merged).
  - **Command = same as skill** (200/100) — commands and skills share internal
    logic (user confirmed; docs: "Custom commands have been merged into skills").

## Decisions

1. Limits are TOKEN-based, enforced via a tiered estimator. CJK worst-case CHAR
   fallbacks (= the user's original numbers) are the Tier-3 backstop semantics.
2. **Tiered estimator** (`scripts/cpv_token_estimate.py`):
   - Tier 1 (opt-in, exact): Anthropic `count_tokens` API when `--exact-tokens`
     / `CPV_TOKEN_EXACT=1` AND `ANTHROPIC_API_KEY` present.
   - Tier 2 (auto, optional dep): tiktoken `o200k_base` × Claude-correction
     (≈1.3 — Claude tokenizes ~20–25% heavier than tiktoken). Used iff importable.
   - Tier 3 (DEFAULT, always available, pure stdlib): Unicode-script-aware
     per-char estimate. Per-SCRIPT chars/tok ratios (Latin/Cyrillic/Greek 4.0,
     CJK/Kana/Hangul 1.0, Thai/Lao/Khmer/Myanmar 1.5, Indic 1.6, Arabic/Hebrew
     2.0, symbols/emoji/unknown 1.0) + ×1.2 safety margin. Conservative: rounds
     up, unknown script → worst case. tiktoken NOT installed in CPV env →
     stdlib is the real default; this is fine because per-script (not a single
     global average) already recovers ~4× fairness for Latin authors.
3. Severity = **MAJOR** for every over-limit (invalid; "no exceptions"). 500-line
   over-limit stays MAJOR (matches docs tip).
4. **Remove bypasses**: `cpv.max_chars`, `cpv.max_lines`, `cpv.skill_size_severity`
   — deleted from readers + load_cpv_config docstring. Emit a WARNING if a
   plugin still declares any (fail-loud "no longer supported").
5. Findings carry the estimate + method + how to get exact ("≈N tok (stdlib est.;
   pass --exact-tokens for precise)"). #43 stays WONTFIX (no override to honor;
   the soft-5000 MINOR is removed entirely).

## Final limits

| Surface | tokens | CJK-worst-case char fallback |
|---|---|---|
| Skill body | 5,000 (+ 500-line MAJOR) | 5,000 |
| Skill `description` | 200 | 200 |
| Skill `when_to_use` | 100 | 100 |
| Command `description` / `when_to_use` | 200 / 100 | 200 / 100 |
| Agent `description` | 300 | 300 |
