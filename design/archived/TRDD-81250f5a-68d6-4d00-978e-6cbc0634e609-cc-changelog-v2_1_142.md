## Context

Anthropic shipped Claude Code v2.1.142. Auditing its changelog against
CPV's coverage surfaced four items that touch plugin validation. Three
were already enforced correctly (regression-locked here); one — the
root-level `SKILL.md` feature — was a genuine gap.

## The four items

### Item A — root-level `SKILL.md` surfaced as a skill (NEW behaviour)

> *Plugins with a root-level `SKILL.md` and no `skills/` subdirectory are
> now surfaced as a skill.*

Before v2.1.142 a plugin's skills had to live in `skills/<name>/SKILL.md`.
Now a `SKILL.md` at the plugin root (when there is no `skills/` subdir) is
auto-surfaced as a skill. CPV did not know this:

* `validate_skills` saw no `skills/` directory, emitted the INFO
  *"No skills/ directory found"*, and returned — the root-level
  `SKILL.md` was never validated at all.
* `validate_structure`'s "manifest but no content" check did not count a
  root-level `SKILL.md` as content — a skill-only plugin got a false
  MAJOR.
* `_discover_plugin_skills` returned an empty set, so a monitor's
  `on-skill-invoke:<root-skill>` reference would be falsely flagged.

### Item B — `skills: ["./"]` no longer false-flags a path escape

> *Fixed plugins using `skills: ["./"]` showing a false "path escapes
> plugin directory" error.*

CPV does **not** have this false positive. `validate_manifest_skill_paths`
resolves `(plugin_root / "./")` → the plugin root, and
`Path.relative_to(plugin_root)` succeeds (the root is in-bounds). Verified
and regression-locked; no code change.

### Item C — prompt/agent hooks rejected for `SubagentStart`

> *Configuring a prompt- or agent-type hook for
> `SessionStart`/`Setup`/`SubagentStart` now shows a clear error.*

A CC error-message improvement, not a schema change. CPV already rejects
prompt/agent hooks for all three events: `SessionStart`/`Setup` are in
`COMMAND_STRICT_EVENTS` (reject http/prompt/agent), `SubagentStart` is in
`COMMAND_ONLY_EVENTS` (reject prompt/agent). Verified and regression-locked;
no code change.

### Item D — every shadowing `plugin.json` key is named

> *Fixed plugin advisories not naming every `plugin.json` key that
> shadows a default folder.*

CPV's v2.84.0 default-folder shadow detection iterates all four
default-folder keys (`commands`, `agents`, `outputStyles` via
`_DEFAULT_COMPONENT_FOLDERS`, plus `skills`) and emits a separate MAJOR
per shadowing key. Verified and regression-locked; no code change.

## Fix (v2.87.0) — Item A only

### `scripts/validate_skill_comprehensive.py`

A root-level `SKILL.md` has no `skills/<name>/` directory — its directory
*is* the plugin root, whose name (often a version string under the plugin
cache, e.g. `…/my-plugin/0.4.4/`) is unrelated to the skill name. The
frontmatter-name vs directory-name match would therefore be a guaranteed
false positive. New opt-in parameter:

* `validate_skill(..., skip_dir_name_check: bool = False)` — threaded to
  `validate_name_field(..., skip_dir_name_check=...)`, which passes
  `directory_name=None` to `validate_component_name` when set. Default
  `False` keeps every existing caller unchanged.

### `scripts/validate_plugin.py`

* **`validate_skills`** — when there is no `skills/` directory and
  `plugin.json` declares no `skills` field, a root-level `SKILL.md` is now
  validated with the full comprehensive validator
  (`validate_skill_comprehensive(plugin_root, strict_mode=True,
  skip_dir_name_check=True)`) — the same scrutiny a `skills/<name>/` skill
  gets. When a `skills/` directory *does* exist, a stray root-level
  `SKILL.md` is dead weight (CC surfaces it only when there is no
  `skills/` subdir) — CPV emits a MINOR telling the author it will not
  load.
* **`_discover_plugin_skills`** — when there is no `skills/` directory, a
  root-level `SKILL.md`'s frontmatter `name` is read (new helper
  `_read_skill_md_name`, fail-safe on any read/parse error) and returned
  so monitor `on-skill-invoke:` cross-referencing works.
* **`validate_structure`** — the "manifest but no content" check now
  counts a root-level `SKILL.md` as content (added to `file_indicators`);
  message updated.

## Tests

`tests/test_v2_1_142_changelog.py` — NEW, 16 tests:

* Item A (8): root-level `SKILL.md` surfaced; defect in a root-level
  `SKILL.md` is caught (validator actually runs); good root-level skill →
  no CRITICAL; no directory-name-mismatch false positive; skill-only
  plugin not flagged "no content"; root `SKILL.md` + `skills/` dir →
  MINOR; `_discover_plugin_skills` includes the root skill; and ignores
  it when `skills/` exists.
* Item B (2): `skills: ["./"]` + root `SKILL.md` → no escape error;
  `skills: ["./"]` with no root `SKILL.md` → MAJOR names the real defect
  (missing `SKILL.md`), never an escape error.
* Item C (5): prompt/agent hooks rejected for `SubagentStart`,
  command-type accepted; `Setup`/`SessionStart` prompt/agent rejected.
* Item D (1): a `plugin.json` shadowing all four default folders →
  a separate MAJOR names each of `commands`/`agents`/`outputStyles`/`skills`.

## Deferred / explicitly not implemented

* **Deep-validating `skills`-path-list entries.** When `plugin.json`
  declares a `skills` array, `validate_manifest_skill_paths` checks only
  that each path exists / contains a `SKILL.md` — it does not run the
  comprehensive content validator. This is pre-existing behaviour
  (path-list skills have always been existence-checked only, exactly like
  the `skills/` auto-discovery vs path-list split). The v2.1.142
  changelog does not ask to change it. Auto-discovered skills (`skills/`
  dir AND now root-level `SKILL.md`) get deep validation; explicitly
  path-listed skills get existence checks. Revisit only if a future
  changelog item makes the path-list authoritative for content too.

## Lessons

Three of four changelog items needed no code — only regression tests.
The audit value is confirming "already correct" with a test that pins the
behaviour, not assuming a code change is owed for every changelog line.
Item B in particular: the CC bug (a false path-escape error) was a CC
implementation defect; CPV's independent path-resolution never had it —
proven by a test rather than assumed.
